# 006 — 客戶驗收、文件與正式交付

## 目標

讓客戶可依操作手冊獨立完成日常營運，並完成系統、資料、帳號與文件交接。

## 驗收角色

- 系統管理者
- 日常營運操作者
- 帳務確認者
- 開發／維護者

MVP 若只有單一管理員帳號，角色僅作驗收分工，不表示系統已有 RBAC。

## 真實驗收案例

1. 20 呎裸櫃年租，分兩期付款。
2. 20 呎裝潢櫃首年優惠。
3. 兩個 10 呎櫃放在同一份合約。
4. 一筆應收分兩次付款。
5. 提前 30 天退租。
6. 遙控器遺失，從押金扣抵。
7. 合約到期續約並調整價格。
8. 欠款客戶續約警告。
9. 退租後貨櫃進入維修。
10. 同一貨櫃重複出租被阻擋。
11. Dashboard 與 Google Sheets 人工核對一致。
12. CSV 於 Excel 開啟中文正常。
13. Session 過期後重新登入。
14. 手機完成查詢及登記收款。

## 操作手冊最低內容

- 登入與登出
- Dashboard
- 客戶建檔
- 貨櫃建檔
- 費率設定
- 建立合約
- 登記收款
- 續約
- 退租
- 支出
- 報表匯出
- 文件中心
- 常見錯誤
- 備份及聯絡方式

## 已知限制

交付前必須明列：

- Google Sheets 非交易型資料庫。
- GAS 執行及流量限制。
- 單一管理員或目前權限模型。
- PWA 不支援離線業務資料同步。
- 尚未整合金流、電子簽章、LINE 與門禁。
- 需保留人工備份及異常核對程序。

## 正式交接

- 系統網址
- 管理員帳號
- Google Sheets 所有權
- GAS 專案權限
- GitHub Repository 權限
- 網域及部署平台權限
- 備份位置
- 問題回報流程
- 維護責任與保固範圍

## Release

1. 最終 Review。
2. 合併功能分支。
3. 建立 Git Tag：

```text
v1.0.0
```

4. 發布 Release Notes。
5. 封存驗收測試結果。
6. 建立正式備份。

## 驗收條件

- [ ] 客戶依手冊可自行完成核心流程。
- [ ] 真實驗收案例全部通過。
- [ ] 已知限制已書面揭露。
- [ ] 帳號、所有權及備份位置已交接。
- [ ] 操作、部署、備份及疑難排解文件完成。
- [ ] 驗收紀錄簽核。
- [ ] `v1.0.0` 建立。
- [ ] 正式資料完成初始備份。
